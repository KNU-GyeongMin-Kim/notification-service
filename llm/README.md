# LLM 관리 및 공지사항 데이터 파이프라인

> **담당자:** 김경민, 전수민  
> **사용 모델:** Ollama (`Qwen3` 등 — *추후 확정 / TBD*)

---

## 개요
본 모듈은 대학 공지사항 원문 데이터를 수집·가공하여 검색 증강 생성(RAG) 기반의 질의응답 환경을 구축하고, LLM을 활용해 공지사항의 핵심 정보를 구조화 및 자동 분류하는 핵심 백엔드 파이프라인입니다.

---

## 주요 기능 및 아키텍처

### 1. LLM - 데이터베이스(DB) 인터페이스 구축
비정형 공지사항 텍스트를 벡터화하여 저장하고, 관계형 데이터베이스와 유기적으로 연동하여 정확한 검색 결과를 반환합니다.

* **텍스트 Chunking 및 Embedding 연동**
  * 공지사항 원문 텍스트를 의미 단위로 분할(Chunking)
  * 임베딩 모델을 통해 벡터 변환 후 Vector DB에 적재
* **RDB - Vector DB 메타데이터 식별자 동기화**
  * 관계형 DB(RDB)의 원본 게시글 PK/ID와 Vector DB 내 벡터 청크 메타데이터 간 식별자 매핑 및 정합성 유지
* **RAG 기반 자연어 검색 파이프라인**
  * 사용자의 자연어 검색 질의를 임베딩 벡터로 변환
  * Vector DB 내 코사인 유사도(Cosine Similarity) 기반의 연관 문서 탐색 및 컨텍스트 추출
* **API 예외 처리 및 안정성 확보**
  * LLM 추론 호출 시 발생하는 응답 지연(Latency) 및 타임아웃(Timeout) 핸들링
  * 컨텍스트 길이(Max Token) 초과 방지를 위한 텍스트 트런케이션(Truncation) 및 예외 복구 로직 적용

---

### 2. 공지사항 데이터 가공 및 자동 분류 엔진
수집된 공지사항 텍스트를 LLM에 전달하여 정형화된 데이터로 변환하고, 변경 이력을 추적합니다.

* **데이터 처리 파이프라인**
  * 크롤러/서버로부터 전달받은 공지사항 원문 텍스트를 전처리 후 LLM 프롬프트에 주입
* **프롬프트 기반 핵심 정보 JSON 자동 추출**
  * 비정형 본문에서 주요 메타데이터(**신청 기간, 지원 대상, 제출 서류, 문의처** 등)를 파싱하여 표준화된 `JSON` 포맷으로 구조화
* **AI 자동 카테고리 태깅 및 분류**
  * 공지사항의 문맥을 파악하여 **학사 / 장학 / 취업 / 행사** 등 지정된 카테고리로 자동 분류 및 태그 부여
* **수정·정정 공지 변경 사항 감지 및 동기화**
  * 기존 공지와 동일한 맥락의 수정/정정 공지 등록 시, 이전 버전과의 핵심 변경 내역(일정 변경, 자격 요건 수정 등)을 비교·감지
  * 추출된 변경 사항(Diff) 요약 데이터를 메인 서버로 전송

## 전체 처리 흐름 (Workflow)

```text
[공지사항 원문 유입]
       │
       ├──▶ 1. 전처리 및 Chunking ──▶ Embedding ──▶ [Vector DB 적재] (RDB ID 동기화)
       │
       └──▶ 2. LLM 프롬프트 처리 (Ollama / Qwen3)
                 ├── 핵심 정보 JSON 추출 (기간, 대상, 서류 등)
                 ├── 카테고리 자동 태깅 (학사/장학/취업/행사)
                 └── 수정/정정 공지 비교 감지 ──▶ [메인 서버 전송]
