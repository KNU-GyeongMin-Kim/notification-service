# 크롤러 (crawler)

학과 게시판에서 공지사항을 주기적으로 가져와 데이터베이스에 저장하는 모듈입니다.

- 담당: 김문수
- 브랜치: `feature/crawler`

## 하는 일

1. 학과 게시판 목록 페이지에서 글번호, 제목, 날짜, 링크를 가져옵니다.
2. 데이터베이스에 저장된 마지막 글번호와 비교해 새 글만 골라냅니다.
3. 새 글의 상세 페이지에서 본문, 이미지 주소, 첨부파일 이름을 가져옵니다.
4. 데이터베이스에 저장합니다. 이미 있는 글은 다시 저장하지 않습니다.
5. 저장한 새 공지 목록을 서버에 넘깁니다. 서버는 이 목록으로 요약과 알림을 처리합니다.

크롤러는 1~3번까지 하고 공지 목록을 돌려줍니다. 4번 저장은 데이터베이스 모듈이 완성되면 연결합니다.

## 시스템 안에서의 위치

```
학과 게시판 ──(크롤링)──> 크롤러 ──(저장)──> 데이터베이스
                            │
                            └──(새 공지 목록)──> 서버 ──> 요약 ──> 알림
```

서버의 스케줄러가 10분마다 크롤러를 실행합니다.

## 대상 게시판

| 게시판 | 주소 |
|---|---|
| 컴퓨터학부 학부 공지사항 | https://aicollege.knu.ac.kr/bbs/board.php?bo_table=sub6_1_a&lang=kor |

- 한 페이지에 글 15개가 최신순으로 나옵니다.
- 게시판 자체 분류가 있습니다: 일반공지, 학사, 장학, 심컴, 첨컴, 인컴, 글솝, 플솝[구.심컴], ICT융합[학부]

## 파일 구성

| 파일 | 내용 |
|---|---|
| `config.py` | 게시판 주소, 요청 간격 등 설정 값 |
| `board.py` | 목록·상세 페이지를 가져오고(`fetch_*`) 필요한 정보를 뽑는(`parse_*`) 함수 |
| `crawl.py` | 새 글 찾기와 본문 수집을 묶은 진입점 (`crawl_new`) |

## 사용 방법

### 다른 모듈에서 쓰기

```python
from crawler.crawl import crawl_new

notices = crawl_new(last_post_no=29515)  # 29515번보다 새 글만, 오래된 글부터
notices = crawl_new()                    # 첫 실행: 첫 페이지 15개
```

### 명령줄에서 시험하기

저장소 최상위 폴더에서 실행합니다.

```
pip install -r requirements.txt
python -m crawler.crawl                              # 첫 페이지 15개를 화면에 출력
python -m crawler.crawl --last 29516                 # 29516번보다 새 글만
python -m crawler.crawl --last 29516 --out notices.json   # 파일로 저장
```

요청 사이에 10초씩 쉬므로 15개를 가져오는 데 약 2분 40초 걸립니다.

## 넘겨주는 데이터 형식

공지 하나를 아래와 같은 사전(dict) 형태로 만듭니다. 이름은 데이터베이스 공지 테이블과 맞춥니다.

```python
{
    "post_no": 29519,                # 게시판 글번호 (주소의 wr_id, 새 글 판별 기준)
    "title": "2026년 하반기 안전교육 미이수자 확인 및 안전교육 이수 방법 안내",
    "date": "2026-11-13 17:14",      # 게시 일시
    "url": "https://aicollege.knu.ac.kr/bbs/board.php?bo_table=sub6_1_a&wr_id=29519",
    "content": "안녕하세요 학생 및 연구원 여러분, ...",  # 본문이 없으면 빈 문자열
    "board_category": "일반공지",     # 게시판 자체 분류 (AI 카테고리와 별개)
    "images": ["https://.../thumb-....png"],          # 본문 이미지 주소
    "attachments": ["안전교육 이수 방법 안내 파일.pdf"],  # 첨부파일 이름
    "collected_at": "2026-11-14 13:49:51",  # 수집 시각
}
```

- 게시판 화면의 "번호"(예: 7041)는 글이 지워지면 바뀌므로 쓰지 않고, 주소의 `wr_id`를 글번호로 씁니다.
- 본문 속 링크는 `글자 (주소)` 형태로 남깁니다. 신청 링크를 요약에 쓸 수 있게 하기 위해서입니다.

## 사용 도구

- `requests`: 웹 페이지 요청
- `beautifulsoup4`: 페이지에서 원하는 부분 찾기

## 주의 사항

- 사이트 `robots.txt`를 확인했습니다. 일반 프로그램은 게시판 접근이 허용되고, `Crawl-delay: 10`이 지정되어 있어 요청 사이에 10초 간격을 둡니다. `/data/`(이미지·파일 저장 경로)는 수집 금지라서 이미지는 주소만 저장하고 내려받지 않습니다.
- 첨부파일 다운로드 주소는 시간이 지나면 만료되므로 파일 이름만 저장합니다. 사용자에게는 원문 링크로 안내합니다.
- 상세 페이지를 열 때마다 게시판 조회수가 1씩 올라갑니다. 같은 글을 반복해서 가져오지 않습니다.
- 첫 실행 때는 기존 글을 저장만 하고 알림은 보내지 않습니다. 기존 글 알림이 한꺼번에 발송되는 것을 막기 위해서입니다. (서버 쪽에서 처리)
- 본문 없이 이미지나 첨부파일만 있는 공지는 본문이 빈 문자열이 됩니다. `images`, `attachments`로 확인하고 원문 링크로 안내합니다.
- 본문 가져오기에 실패하면 그 글부터 멈추고 기록을 남깁니다. 다음 주기에 다시 시도됩니다.
