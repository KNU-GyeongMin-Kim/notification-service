# 크롤러 (crawler)

학과 게시판에서 공지사항을 주기적으로 가져와 데이터베이스에 저장하는 모듈입니다.

- 담당: 김문수
- 브랜치: `feature/crawler`

## 하는 일

1. 학과 게시판 목록 페이지에서 글번호, 제목, 날짜, 링크를 가져옵니다.
2. 가져올 글을 고릅니다. 수집 방식은 두 가지입니다.
   - **기간 수집** (`crawl_since`): 최근 N일 안에 올라온 글을 모두 가져옵니다. DB를 처음 채울 때 씁니다. (기본 365일)
   - **새 글 수집** (`crawl_new`): DB에 저장된 마지막 글번호 이후의 글만 가져옵니다. 10분마다 씁니다.
3. 고른 글의 상세 페이지에서 본문, 이미지 주소, 첨부파일 이름을 가져옵니다.
4. 서버가 받아서 데이터베이스에 저장합니다. 이미 있는 글은 다시 저장하지 않습니다.

크롤러는 1~3번까지 하고 공지를 돌려줍니다. 저장은 서버(`server/jobs.py`)가 합니다.

## 시스템 안에서의 위치

```
학과 게시판 ──(크롤링)──> 크롤러 ──(저장)──> 데이터베이스
                            │
                            └──(새 공지 목록)──> 서버 ──> 요약 ──> 알림
```

서버의 스케줄러가 10분마다 크롤러를 실행합니다.

## 대상 게시판

| 게시판 | 주소 |
|---|---|
| 컴퓨터학부 학부 공지사항 | https://aicollege.knu.ac.kr/bbs/board.php?bo_table=sub6_1_a&lang=kor |

- 한 페이지에 글 15개가 최신순으로 나옵니다.
- 게시판 자체 분류가 있습니다: 일반공지, 학사, 장학, 심컴, 첨컴, 인컴, 글솝, 플솝[구.심컴], ICT융합[학부]

## 파일 구성

| 파일 | 내용 |
|---|---|
| `config.py` | 게시판 주소, 요청 간격 등 설정 값 |
| `board.py` | 목록·상세 페이지를 가져오고(`fetch_*`) 필요한 정보를 뽑는(`parse_*`) 함수 |
| `crawl.py` | 대상 글 고르기와 본문 수집을 묶은 진입점 (`crawl_since`, `crawl_new`) |

## 사용 방법

### 다른 모듈에서 쓰기

```python
from crawler.crawl import crawl_new, crawl_since

# 새 글 수집: 29515번보다 새 글만, 오래된 글부터 목록으로
notices = crawl_new(last_post_no=29515)

# 기간 수집: 최근 365일 글을 최신 글부터 한 건씩 (제너레이터)
# skip 에 넘긴 함수가 True 인 글번호는 건너뜀 -> 이미 저장한 글은 다시 읽지 않음
for notice in crawl_since(days=365, skip=db.notice_exists):
    db.add_notice(notice, is_initial=True)
```

기간 수집은 오래 걸리므로 한 건씩 내줍니다. 받자마자 저장하면 중간에 멈춰도 그때까지는 남고, 다시 실행하면 남은 글만 가져옵니다.

### 명령줄에서 시험하기

저장소 최상위 폴더에서 실행합니다.

```
pip install -r requirements.txt
python -m crawler.crawl --last 29516                 # 29516번보다 새 글만 화면에 출력
python -m crawler.crawl --days 7                     # 최근 7일 글
python -m crawler.crawl --days 7 --out notices.json  # 파일로 저장
```

시험용 명령이라 DB에는 저장하지 않습니다. DB에 넣으려면 `python -m server --backfill 365`를 씁니다.

## 걸리는 시간

요청 사이에 10초씩 쉬므로 글 1건에 약 10초 걸립니다.

| 범위 | 목록 페이지 | 글 수 | 시간 |
|---|---|---|---|
| 새 글 수집 (10분마다) | 1 | 보통 0~2건 | 수십 초 이내 |
| 최근 7일 | 1 | 약 15건 | 약 3분 |
| 최근 365일 | 약 34 | 약 500건 | 약 1시간 30분 |

(2026-11 기준. 1년 전 글이 목록 34페이지 무렵에 있습니다.)

## 넘겨주는 데이터 형식

공지 하나를 아래와 같은 사전(dict) 형태로 만듭니다. 이름은 데이터베이스 공지 테이블과 맞춥니다.

```python
{
    "post_no": 29519,                # 게시판 글번호 (주소의 wr_id, 새 글 판별 기준)
    "title": "2026년 하반기 안전교육 미이수자 확인 및 안전교육 이수 방법 안내",
    "date": "2026-11-13 17:14",      # 게시 일시
    "url": "https://aicollege.knu.ac.kr/bbs/board.php?bo_table=sub6_1_a&wr_id=29519",
    "content": "안녕하세요 학생 및 연구원 여러분, ...",  # 본문이 없으면 빈 문자열
    "board_category": "일반공지",     # 게시판 자체 분류 (AI 카테고리와 별개)
    "images": ["https://.../thumb-....png"],          # 본문 이미지 주소
    "attachments": ["안전교육 이수 방법 안내 파일.pdf"],  # 첨부파일 이름
    "collected_at": "2026-11-14 13:49:51",  # 수집 시각
}
```

- 게시판 화면의 "번호"(예: 7041)는 글이 지워지면 바뀌므로 쓰지 않고, 주소의 `wr_id`를 글번호로 씁니다.
- 본문 속 링크는 `글자 (주소)` 형태로 남깁니다. 신청 링크를 요약에 쓸 수 있게 하기 위해서입니다.

## 사용 도구

- `requests`: 웹 페이지 요청
- `beautifulsoup4`: 페이지에서 원하는 부분 찾기

## 주의 사항

- 사이트 `robots.txt`를 확인했습니다. 일반 프로그램은 게시판 접근이 허용되고, `Crawl-delay: 10`이 지정되어 있어 요청 사이에 10초 간격을 둡니다. `/data/`(이미지·파일 저장 경로)는 수집 금지라서 이미지는 주소만 저장하고 내려받지 않습니다.
- 첨부파일 다운로드 주소는 시간이 지나면 만료되므로 파일 이름만 저장합니다. 사용자에게는 원문 링크로 안내합니다.
- 상세 페이지를 열 때마다 게시판 조회수가 1씩 올라갑니다. 같은 글을 반복해서 가져오지 않습니다.
- 기간 수집한 글은 기존 공지로 저장하고 알림을 보내지 않습니다. 기존 글 알림이 한꺼번에 발송되는 것을 막기 위해서입니다. 새 글 수집이라도 작성된 지 3일이 넘은 글은 알림을 보내지 않습니다. (서버 쪽에서 처리)
- 본문 없이 이미지나 첨부파일만 있는 공지는 본문이 빈 문자열이 됩니다. `images`, `attachments`로 확인하고 원문 링크로 안내합니다.
- 본문 가져오기에 실패하면, 새 글 수집은 그 글에서 멈추고 다음 주기에 다시 시도합니다. 기간 수집은 그 글만 건너뛰고, 다시 실행하면 그 글을 다시 시도합니다.
